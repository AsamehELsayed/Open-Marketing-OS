# Open Marketing OS — release history

This file records what was actually released, and — just as importantly — what
was claimed and then found to be untrue.

> **Corrected during DEV-008-PUBLISH-GATE, before any public release.**
>
> An earlier version of this file was titled *"v1.0.0 Release Notes"* and
> described `OMOS-Qwen2.5-7B-Marketing-v1` as the primary shipped marketing
> model, presented a 15-row table of "Marketing LoRA Adoption Evidence" scored
> 100% in favour of that adapter across named business verticals, and declared
> a "FROZEN / APPROVED" status.
>
> **None of that was true.** No adapter artifact was ever produced. A license and
> asset audit (`docs/opensource/license-audit.md` §5) found zero `.gguf` files and
> zero trained weights anywhere in the tree, and recorded the local-marketing
> acceptance gate as **FAIL — the artifact does not exist**, not "pending". The
> 15-row evaluation table cannot be evidence of anything, because the model it
> claims to compare does not exist, and several of its rows named real
> businesses, one of which was a client.
>
> v1.0.0 was an **internal development milestone**, never published, and never
> installed by a user. The first release any member of the public receives is
> [`v1.1.0-beta.1`](../../CHANGELOG.md). The false document has been replaced
> rather than deleted so the correction is auditable.

## v1.0.0 — internal milestone, never released

**Date:** 2026-09-22
**Published:** No. No tag was pushed and no artifact was distributed.

### What it actually established

These parts were real, were verified at the time, and did carry forward:

1. **Agentic graph orchestration (LangGraph).**
   Stateful execution graph with an in-memory checkpointer and persistent
   SQLite storage (`marketing.db`). Multi-agent fan-out and deep research using
   LangGraph's `Send` primitive. Deterministic routing for `state_only`,
   `knowledge`, `deep_research`, `social_research` and `synthesize`.

2. **Provider routing and telemetry.**
   A `ModelRouter` layer over a provider interface, with concrete OpenRouter and
   OpenAI providers and a fake provider for tests. Per-call telemetry persisted
   to SQLite `model_calls`: provider, model, adapter, quantization, input/output
   tokens, latency, estimated cost and pricing version. Fail-closed project
   isolation: a request without a valid project scope is rejected before any
   model call.

3. **Real-time streaming and observability.**
   Server-Sent Events delivering incremental text deltas, plus a structured
   event bus (`thread_started`, `state_read`, `tool_started`, `tool_completed`,
   `synthesis_started`, `model_completed`, `turn_completed`).

4. **Human-in-the-loop approvals.**
   High-impact and external-facing actions interrupt execution
   (`status: interrupted`); approval resumes the graph deterministically. A
   post-synthesis guardrail bounds unqualified quantitative growth claims as
   hypotheses or relative targets.

5. **React single-page frontend.**
   A modular SPA with SSE subscriptions and an accessible, keyboard-navigable
   model-routing badge.

### What it did not establish

- **No local model shipped.** The local `llama.cpp` provider exists in the tree
  and is reachable in development. No model weights and no adapter were ever
  built, and none are distributed.
- **No Marketing LoRA exists.** Training *tooling* is present
  (`app/evals/models/lora_*.py`) and its acceptance gate is deliberately closed
  and marked `NOT_RUN`. A tool that can train a model is not a trained model.
  Nothing in this repository should be read as evidence that a marketing adapter
  was produced, benchmarked, or preferred over anything.
- **No A/B evaluation is claimed.** The removed table recorded preferences for a
  model that does not exist, against a baseline that was not shipped either.
- **The test count was wrong.** The figure quoted at the time (364) is stale. See
  `CHANGELOG.md` and the CI workflow for the count that is actually enforced on
  every commit.

### Preserved legacy paths

Still present and still switchable: `AI_RUNTIME=langgraph` remains the default
with the `legacy` path preserved; `ROUTER_MODE=BASE` remains available; ChromaDB
vector search and SQLite full-text search fallbacks both remain active; cloud
providers remain opt-in per credential.

## v1.1.0-beta.1 — first public beta

**Edition:** OMOS Quick (Windows x64).
**Cloud AI:** OpenRouter or OpenAI, using your own credential.
**Local AI:** not in this beta. See `CHANGELOG.md` for the full change list and
`README.md` for what users should expect.

Beta 1 ships Quick only. A local-model edition is planned for a later beta and
is not advertised, downloaded, or bundled here.
